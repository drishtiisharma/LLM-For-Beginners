# Prompt Templates — Why They Exist and How to Use Them

I'd been passing raw strings to models and it was working fine — until I realized I was doing things the messy way.
Prompt templates exist to fix that, and once I understood why, a lot of things clicked.

## 1. Why Prompt Templates Even Exist

When I first started, I was doing stuff like this:

```python
prompt = f"You are a helpful assistant. The user asked: {user_input}"
llm.invoke(prompt)
```

It works. But it gets ugly fast — especially when you want to reuse the same structure across different inputs, or when your prompt has multiple moving parts.

Prompt templates let you define the structure once and just fill in the blanks each time.
Think of it like a form letter — the layout stays the same, only the name and date change.

That's the whole idea. It's not magic. It's just cleaner.

## 2. The Different Message Roles

Before templates make sense, you need to understand that LLMs — especially chat models — don't just receive one big blob of text.
They receive a *conversation*, and each message has a **role** that tells the model who's talking.

Here's what each role actually means:

**system**
This is where you tell the model how to behave before the conversation starts.
"You are a helpful assistant that only responds in bullet points." That kind of thing.
It's not part of the dialogue — it's more like the briefing you give someone before they walk into a meeting.

**user**
The human talking to the model. Whatever the person typed goes here.

**assistant**
The model's response. When you're building a multi-turn conversation, you include previous assistant messages so the model knows what it already said.

**tool**
After the model calls an external tool — like a search function or a calculator — the result comes back as a tool message.
The model reads this and uses it to continue its response.

**function (legacy)**
This was OpenAI's older way of doing tool calls. It's been replaced by the tool role.
You'll still see it in older codebases, but don't use it for new stuff.

## 3. LangChain's Message Types

LangChain wraps these roles in Python classes so you're not passing raw dictionaries around.
The mapping is pretty direct:

| LangChain Class | Corresponds To |
|---|---|
| `SystemMessage` | system role |
| `HumanMessage` | user role |
| `AIMessage` | assistant role |
| `AIMessageChunk` | assistant role, but for streaming |
| `ToolMessage` | tool role |

`AIMessageChunk` is the interesting one — when a model streams a response token by token, each chunk comes back as one of these. Once streaming finishes, you assemble them into a full `AIMessage`.

## 4. Why System Messages Actually Matter

I initially treated the system message as optional flavor text.
Turns out it's one of the most important parts of working with chat models.

Without a system message, the model falls back on its default behavior — which is fine, but generic.
The system message is how you actually shape the model into something specific.

A few things I noticed while testing:

- Without a system message, responses tend to be longer and more hedged.
- A clear system message makes outputs much more consistent across different inputs.
- Smaller models respond *much* more noticeably to system messages than larger ones — probably because they have less built-in instruction-following ability.

A simple example of the difference:

```python
# Without system message
HumanMessage("Explain neural networks")
# → Long, textbook-style answer

# With system message
SystemMessage("Explain things like you're talking to a 15-year-old.")
HumanMessage("Explain neural networks")
# → Much more casual, actually readable
```

Same model, same question — completely different tone.


## 5. Prompt Templates with ChatOllama

Here's where it all comes together practically.

LangChain gives you a few template classes. I worked with these four:

**`PromptTemplate`**
The basic one. Takes a plain string with placeholders.

```python
from langchain.prompts import PromptTemplate

template = PromptTemplate(
    input_variables=["topic"],
    template="Explain {topic} in simple terms."
)

prompt = template.format(topic="transformers")
```

Simple, no roles — good for basic completions.

**`SystemMessagePromptTemplate`**
Wraps a template string in a system message.

```python
from langchain.prompts import SystemMessagePromptTemplate

system_template = SystemMessagePromptTemplate.from_template(
    "You are an expert in {domain}. Be concise and clear."
)
```

**`HumanMessagePromptTemplate`**
Same idea, but for the user's message.

```python
from langchain.prompts import HumanMessagePromptTemplate

human_template = HumanMessagePromptTemplate.from_template(
    "Can you explain {concept} to me?"
)
```

**`ChatPromptTemplate`**
The one that ties everything together. You combine system and human templates into a full conversation structure.

```python
from langchain.prompts import ChatPromptTemplate
from langchain_ollama import ChatOllama

chat_prompt = ChatPromptTemplate.from_messages([
    system_template,
    human_template
])

llm = ChatOllama(model="llama3")
chain = chat_prompt | llm

response = chain.invoke({
    "domain": "machine learning",
    "concept": "backpropagation"
})

print(response.content)
```

The `|` operator here is LangChain's way of chaining steps together — format the prompt, then pass it to the model.
It reads left to right, which is a lot cleaner than nesting function calls.


# The Simple Understanding I Finally Reached

Prompt templates are just reusable prompt structures.
Message roles are the model's way of understanding who said what and in what context.
System messages are where you actually control how the model behaves.

Once I stopped thinking of a prompt as a single string and started thinking of it as a structured conversation, the whole templates thing stopped feeling like unnecessary abstraction and started feeling like the obvious way to do it.
